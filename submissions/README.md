# Здача WS8

Здача — **один PR у цей репозиторій з одним новим файлом**:

```text
submissions/<team-slug>/<github-login>.md
```

- `<team-slug>` — `property-workflows`, `therapy-scheduling`, `school-purchasing` або `leave-portal`;
- `<github-login>` — ваш логін GitHub, точно як у профілі (той самий, з якого відкрито PR);
- вміст — за [шаблоном](_template.md), усі поля заповнені, зайва для вашої ролі частина — «—».

Здають окремо: PM і розробники, у кожного — свій файл. Роль у файлі — `pm` або `dev`. Інших файлів PR не змінює: ні
README, ні `docs/`, ні `materials/`, ні чужих файлів у `submissions/`. **Строк — до кінця Вт 03.11** (23:59 за
Києвом).

## Яке репо й SHA вказати

Кожен здає **своє** репо — те саме, що у WS6–WS7:

| Роль | «Ваше репо» | «Репо вимог PM» |
|---|---|---|
| `pm` | репо вимог `https://github.com/<pm>/<team-slug>-spec` | те саме |
| `dev` | своє репо `https://github.com/<dev>/<team-slug>` | репо вимог PM вашої команди |

Конвеєр перевіряє «Ваше репо» **на цьому коміті**, тому коміт має бути запушений, а SHA — повний (40 символів): коміт
`main` вашого репо на момент здачі.

- **Розробник** (PowerShell чи Git Bash):

  ```bash
  git fetch origin
  git rev-parse origin/main
  ```

- **PM (без git):** на сторінці репо вимог відкрийте історію комітів `main` і скопіюйте повний SHA останнього коміту
  кнопкою копіювання біля нього (точну назву перевірте в інтерфейсі). Короткий SHA з 7 символів не підходить.

## Посилання — у якому вигляді

| Що | Де | Вигляд |
|---|---|---|
| PR | ваше репо | `https://github.com/<ваш-логін>/<repo>/pull/N` |
| Файл на SHA (proof pack, звіт UAT, `accounts.zip`, workflow) | ваше репо | `https://github.com/<ваш-логін>/<repo>/blob/<SHA>/docs/qa/proof-pack.md` |
| Тека на SHA (кадри UAT) | ваше репо | `https://github.com/<ваш-логін>/<repo>/tree/<SHA>/docs/qa/uat/2026-11-01` |
| Прогін CI (`quality`, `smoke`, `CI`) | ваше репо | `https://github.com/<ваш-логін>/<repo>/actions/runs/N` |
| Коментар у PR (таблиця рецензента, ключ, повторний прогін) | ваше репо | `…/pull/N#issuecomment-M` |
| `/api/health` | ваш прод | `https://<проєкт>.vercel.app/api/health` |
| Issue «Вимога», «Питання до вимог», коментар «Зміна: …» | репо вимог PM | `https://github.com/<pm>/<team-slug>-spec/issues/N`, `…/issues/N#issuecomment-M` |
| Варіант `docs/`: файл вимоги, розділ, коміт | репо вимог PM | `…/blob/<SHA>/docs/requirements/03-….md`, `…/blob/<SHA>/docs/product.md#як-доводимо`, `…/commit/<sha>` |
| Issue «Відхилення від вимог», коментар-підпис PM | репо розробника | `https://github.com/<dev>/<team-slug>/issues/N`, `…/pull/N#issuecomment-M` |

**Паролів у файлі немає ніде:** акаунти — лише адреси `*@example.test`. Пароль від `accounts.zip` теж ніде не пишемо.

## Покроково: розробник

PowerShell (Git Bash — так само, лише `cp` замість `Copy-Item`):

```powershell
gh repo fork koldovsky/2026-quitcode-08-quality-hw --clone
cd 2026-quitcode-08-quality-hw
git switch -c ws08/<github-login>
Copy-Item submissions/_template.md submissions/<team-slug>/<github-login>.md
# заповніть файл
git add submissions/<team-slug>/<github-login>.md
git commit -m "WS8 submission: <team-slug>/<github-login>"
git push -u origin ws08/<github-login>
gh pr create --repo koldovsky/2026-quitcode-08-quality-hw --web
```

## Покроково: PM (у браузері)

1. Відкрийте [шаблон здачі](_template.md) в цьому репозиторії, перегляньте сирий текст (кнопка Raw; точну назву
   перевірте в інтерфейсі) і скопіюйте його повністю.
2. Перейдіть у теку `submissions/<team-slug>/` цього репозиторію → Add file → Create new file (точні назви перевірте
   в інтерфейсі). GitHub попередить, що права запису у вас немає, і запропонує працювати у вашій копії (fork) — це
   правильно.
3. Ім'я файлу — `<github-login>.md`, вміст — скопійований шаблон. Заповніть поля просто в редакторі. Рядки
   приймання (трек B) — у таблиці приймання PM (Google Таблиця курсу), а не тут. У файлі — рядок «Таблиця
   приймання PM: заповнено» з логінами розробників, звірка, issues і підписи; адресу таблиці не копіюйте.
4. Внизу оберіть створення нової гілки й запропонуйте зміну (Propose new file → Create pull request; точні назви
   перевірте в інтерфейсі).

## Далі — для всіх

Fork цього репозиторію потрібен **лише для здачі**. Ваша робота живе у вашому репо вимог чи репо розробника.

1. Відкриється сторінка нового PR з шаблоном опису. **Заголовок — `WS8: Ім'я Прізвище`.** У шаблоні заповніть
   **«Ім'я та Прізвище»** (обов'язково: сертифікат виписується на реальне ім'я) і роль. Розробник не додає `--fill`:
   з ним опис береться з комітів, і шаблон не підставляється.
2. Цей репозиторій має менше 10 зірок, тому CodeRabbit не почне сам. Напишіть у PR **окремим коментарем**
   `@coderabbitai review`.
3. CodeRabbit перевіряє лише файл здачі: шлях, заповнені поля, SHA, вигляд посилань, відсутність паролів і що нічого
   іншого не змінено. Виправте зауваження в тій самій гілці: розробник — новим комітом і push, PM — правкою файлу у
   своїй копії (іконка олівця на сторінці файлу; точну назву перевірте в інтерфейсі).

Ім'я та прізвище — лише в описі PR, не у файлі: файли цього репозиторію публічні.
